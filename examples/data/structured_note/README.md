# Structured-note examples (worst-of autocallables on index baskets)

Two `price-structured-note` requests transcribed from public IDAD factsheets.
The TERMS (dates, triggers, coupons, barrier, currency, denomination) are the
factsheets'. EVERY MARKET NUMBER IS A PLACEHOLDER: spots, initial levels,
historical closes, dividend yields, volatilities, FX spots and vols, local
rates, the SOFR curve (copied from `examples/data/fx_forward/`), the
correlation matrix, the issuer funding spread and the underlying/FX
correlations are round synthetic values chosen so the requests parse and the
seasoning resolves to a live note. They are not market data and the prices
they produce are not valuations of the notes. The JSON gateway is strict
(unknown fields are rejected), so this file carries that warning instead of
an in-request comment.

| File | Note | ISIN |
|---|---|---|
| `bnp_quad_index_classic_autocall_xs2741509801.json` | BNP Paribas Quad Index Classic Autocall June 2025 | XS2741509801 |
| `santander_quad_index_low_hurdle_autocall_xs3109492564.json` | Santander Quad Index Low Hurdle Autocall August 2025 (USD) | XS3109492564 |
| `bnp_quad_index_classic_autocall_xs2741509801_diagnostics.json` | The BNP request with every `diagnostics` flag on and `sample_paths: 3` (see "Diagnostics") | XS2741509801 |
| `bnp_quad_index_classic_autocall_xs2741509801_greeks.json` | The BNP request with `greeks` on at the default bump sizes (see "Greeks") | XS2741509801 |
| `synthetic_two_asset_worst_of_flat_vol_autocall.json` | Synthetic: two USD indices (flat 25 % / 30 % vols, rho 0.7), worst-of, four semi-annual 100 % autocalls with 5 % snowball coupons, 70 % European barrier, 1024 paths | none (test case) |
| `single_underlying_reverse_convertible.json` | Synthetic reverse convertible on SPX alone: eight quarterly 2 % coupons paid unconditionally (`coupon_trigger: 0.0`, no `autocall_trigger`, no memory), 70 % European barrier at the final observation, SOFR + 80 bp; no `correlation_id` (a single underlying is simulated on the 1 x 1 unit matrix) | none (test case) |

The synthetic two-asset file is generated by `two_asset_request()` in
`tests/contract/structured_note_parity_test.py` (a test asserts they are
equal); it is a small, fast parity and catalog case, not a product. A note
with two or more underlyings needs a `CorrelationMatrixSpec` (at least two
labels) and `correlation_id`; a single-underlying note must omit
`correlation_id`.

Valuation date in both: `pricing.as_of_date = 2026-10-21`. Both notes are
seasoned at that date (one dated observation has passed), so the past
observation is resolved from `historical_levels`, never simulated.

## Factsheet line -> field

| Factsheet | Field |
|---|---|
| Underlying basket (Bloomberg codes SMI, SPX, SX5E, NKY) | `notes[].underlyings[].underlying_id` -> `pricing.equity.equity_underlyings[].id`; the currency of each (`CHF`, `USD`, `EUR`, `JPY`) is on the `EquityUnderlyingSpec` |
| Currency USD | `notes[].currency`; the three non-USD indices carry a `quanto` block (FX spot, FX vol, underlying/FX correlation, local-currency rate curve) |
| Denominations 1,000 | `notes[].notional = 1000` (one unit) |
| Strike date (27 June 2025 / 21 August 2025) | not a field: the strike closes are `underlyings[].initial_level` |
| "all of the Underlyings at or above" | `performance_rule = WorstOf` |
| Autocall Trigger 100% | `events[].autocall_trigger = 1.0` on every dated observation |
| Coupon Rate 7.00% semi-annually / 2.50% quarterly | `events[].coupon = 0.07` / `0.025` on every event (accrual-only ones included) |
| "Snowballing coupon", "for each period elapsed", paid on call | `coupon_rule = {memory: true, pay_only_on_call: true}` |
| First Observation at 12 months (periods before it earn a coupon) | accrual-only events with NO trigger and NO payment date: BNP one (`2025-12-29`), Santander three (`2025-11-21`, `2026-02-23`, `2026-05-21`). Their dates are the period ends implied by the schedule, rolled to the next business day; only their order matters (they must precede the first observation), nothing is observed on them and no historical level is needed |
| Observation dates table (observation date, payment date, 100%) | one `ObservationEvent` per row, dates copied verbatim (`observation_date`, `payment_date`) |
| Final Observation + "80% Low Hurdle" (Santander) | the last event carries `coupon_trigger = 0.8` and no `autocall_trigger`: at the final observation a call and a coupon-plus-redemption pay the same amounts on the same date, so the 80% hurdle is the only test that matters |
| Final Observation + 100% (BNP) | the last event carries `autocall_trigger = 1.0` (coupon test = call test) |
| Final valuation date that only decides the redemption (Scotia: 75% trigger and 250% upside, no coupon, no call) | the last event is `{observation_date, payment_date, is_final: true}`: only `capital` (and `upside`) is tested there; `coupon`, `coupon_trigger` and `autocall_trigger` must be absent and `payment_date` must equal `maturity_payment_date` |
| Capital Protection Barrier 60% Final level (European style) | `capital = {barrier: 0.6, monitoring: European}` |
| "capital return reduced on a 1-for-1 basis" | `capital.put_strike = 1.0`, `capital.participation = 1.0` |
| Maturity Date (07 July 2031 / 28 August 2031) | `maturity_payment_date` |
| Issuer / credit rating | `discounting_curve = USD_SOFR_OIS` plus `funding_spread_bp` (placeholder 100) |
| Daily pricing, secondary market | not modelled; the engine returns the model value, no bid/offer |

Event counts: BNP 12 events (1 accrual-only + 10 observations + final),
Santander 24 (3 accrual-only + 20 observations + final).

## Market-data placeholders (where to put real data)

- `pricing.quotes`: spot of each index (`<ID>_SPOT`).
- `pricing.rates.curves`: `USD_SOFR_OIS` (OIS helpers), flat local-currency
  curves `CHF_FLAT`, `EUR_FLAT`, `JPY_FLAT` (quanto drift), flat dividend
  curves `<ID>_DIV`.
- `pricing.volatility.vol_surfaces`: flat `BlackVolSpec` per index
  (`<ID>_VOL`) and per FX pair (`CHFUSD_VOL`, `EURUSD_VOL`, `JPYUSD_VOL`). A
  term structure or a strike x expiry surface goes in the same slot (a
  surface requires `monte_carlo.steps_per_year`).
- `pricing.fx.spots`: `CHFUSD_SPOT`, `EURUSD_SPOT`, `JPYUSD_SPOT`.
- `pricing.correlations.matrices[0]`: `QUAD_INDEX_CORR`, labels in basket
  order, row-major values; must be positive semi-definite.
- `underlyings[].initial_level`: the strike-date closes.
- `underlyings[].historical_levels`: the closes on past dated observations
  (BNP `2026-06-29`, Santander `2026-08-21`). The placeholders leave the
  worst performer below 100% so neither note is already called.
- `underlyings[].quanto.fx_underlying_correlation`: correlation between the
  index and the FX rate (index currency per unit of USD).
- `notes[].funding_spread_bp`: issuer funding over SOFR.

## A real note against its published value: Bank of Nova Scotia 06419JME7

`scotia_autocallable_trigger_ndx_rty_us06419jme72.json` is the Bank of Nova Scotia
Autocallable Trigger Notes linked to the worst of the Nasdaq-100 and the Russell 2000
(SEC pricing supplement 424B2, filed 2026-10, CUSIP 06419JME7 / ISIN US06419JME72). It is
the only example whose market data is real, and the filing publishes the issuer's own
initial estimated value, **$973.52 per $1,000**, so the engine can be compared with it. The filed document is
`scotia_autocallable_trigger_ndx_rty_us06419jme72_sec_424b2.pdf` (EDGAR HTML printed to PDF).

Terms, from the filing: trade date 2026-09-30, initial levels NDX 30,408.50 and RTY
2,796.864; one call observation on 2027-09-30 paid on 2027-10-05 at 100% plus a 14.75%
call premium if both indices close at or above their initial levels; otherwise at the
valuation date 2028-10-02, paid on 2028-10-05: 100% plus 250% of the worst return when
that return is positive, 100% when the worst index is at or above its 75% trigger, and
1-for-1 with the worst index below it. No coupons, USD, price-return indices.

In the form: one event with `autocall_trigger` 1.0 and `coupon` 0.1475, and a final event
`{observation_date: 2028-10-02, payment_date: 2028-10-05, is_final: true}`: a maturity-only
observation that tests nothing but the 75 % trigger and the upside (no coupon, no call, so
no `coupon` and no trigger; its `payment_date` is the `maturity_payment_date`). Before
`is_final` existed the same date was written as `coupon_trigger` 0.0 with `coupon` 0.0, which
prices identically on the same stream; the marker says what the filing says. `memory` false,
`capital` barrier 0.75 European with put strike 1.0, and `upside` strike 1.0 with
participation 2.5.

Market data as of 2026-09-30, all from primary sources:

| Input | Value | Source |
|---|---|---|
| USD curve | Treasury par yields 1M 4.02, 3M 4.20, 6M 4.33, 1Y 4.54, 2Y 4.88, 3Y 5.00, bootstrapped to continuous zeros (4.49% at 1Y, 4.83% at 2Y) | US Treasury daily par yield curve |
| Overnight SOFR (for reference) | 3.90% | NY Fed |
| NDX vol | 22.46% flat (VXN close) | Cboe VXN |
| RTY vol | 21.56% flat (RVX close) | Cboe RVX |
| Correlation | 0.747, one year of daily log returns to 2026-09-30 | index closes |
| Dividend yields | NDX 0.43% (QQQ trailing), RTY 0.98% (IWM 12-month trailing as of 2026-09-30) | fund pages |
| Funding spread | 0 bp (the filing says the Bank's internal funding rate is below its bond spread and does not state it) | SEC filing |

Result (65,536 Sobol paths; 262,144 gave the same numbers to the standard error):

| | Engine | Filing |
|---|---:|---:|
| Price per 1,000 | 965.6 ± 0.4 | 973.52 |
| Probability of the call at year one | 0.41 | not stated |
| Probability of a trigger breach at maturity | 0.20 | not stated |
| Bond redemption / coupon / capital-loss legs | 975.2 / 57.7 / −67.2 | not stated |

The gap of 0.8% of notional sits inside the uncertainty of the inputs the filing does not
publish. Sensitivities from the same request: vols two points lower, 978.2; zero dividends,
974.8; correlation 0.9, 984.1; funding 50 bp, 958.2; correlation 1.0 (single-index limit),
1,011.3; correlation 0, 908.4. The 30-day volatility indices are proxies for the one- and
two-year at-the-money vols, and flat vols carry no skew, which under-prices the 75% trigger
put; option-implied surfaces and forwards from one day of NDX and RUT option quotes are the
inputs that would turn this into a reconciliation rather than a comparison.

## A second real note: JPMorgan Review Notes 46661PT64

`jpm_review_notes_ndx_rty_spx_46661pt64.json` is JPMorgan Chase Financial's Review Notes
linked to the least performing of the Nasdaq-100, the Russell 2000 and the S&P 500 (SEC
pricing supplement 424B2 filed 2026-10-21, pricing date 2026-10-19, CUSIP 46661PT64; the
filed document is `jpm_review_notes_ndx_rty_spx_46661pt64_sec_424b2.pdf`). Five-year note,
49 monthly review dates from 2027-10-21: on the first review date where all three indices
close at or above their initial levels the note is called at 100% plus a call premium that
grows by 0.73333% per month, from 8.80% at the first review date to 44.00% at the final one
(2031-10-20, paid at maturity 2031-10-23). Not called: 100% if every index is at or above
70% of its initial level, otherwise 1-for-1 with the least performing index. No coupons,
no upside participation. Estimated value on the pricing date: **$937.30 per $1,000**.

In the form: 49 events, each with `autocall_trigger` 1.0; `coupon` 0.088 on the first and
0.44/60 on every later one, `memory` true and `pay_only_on_call` true, so the memory sum at
event i is exactly the filed premium; `capital` barrier 0.70 European. Initial levels NDX
29,529.34, RTY 2,728.298, SPX 7,690.73.

Market data as of 2026-10-19, primary sources: Treasury par yields (1M 4.11 … 5Y 4.94, 7Y
5.04) bootstrapped to continuous zeros; VXN 25.56, RVX 22.91, VIX 18.44 closes as flat vols;
correlation from one year of daily log returns (NDX-RTY 0.746, NDX-SPX 0.925, RTY-SPX 0.831);
dividend yields QQQ 0.43%, IWM 0.99%, SPY 0.98%; funding spread 0 bp.

| | Engine (65,536 paths) | Filing |
|---|---:|---:|
| Price per 1,000 | 911.8 ± 0.9 | 937.30 |
| Probability of a call at the first review date / ever | 0.38 / 0.75 | |
| Probability of a barrier breach at maturity | 0.19 | |
| Expected life | 2.4 years | |
| Bond redemption / premium / capital-loss legs | 893.6 / 92.6 / −74.5 | |

The 2.7% gap is larger than the Scotia note's and is what a five-year worst-of on 30-day vol
proxies should produce: vega is about −8 per vol point across the three indices and the
VXN close used here sits in a spike (27.1 on 10-16 from about 21 a week earlier), while a
five-year at-the-money vol is a different number altogether. Sensitivities: vols two
points lower, 928.0; five points higher, 873.2; zero dividends, 923.9; pairwise
correlations 40% closer to one, 924.5; funding 50 bp, 902.5; rho −0.08 per bp, so a funding
curve 30 bp below Treasuries adds about 2.3. Correlation limits from the checks block:
959.9 at one, 786.9 at zero; bond-only value 782.4.

## Diagnostics

`bnp_quad_index_classic_autocall_xs2741509801_diagnostics.json` adds

```
"diagnostics": {"market": true, "decomposition": true, "checks": true,
                "distribution": true, "timing": true, "sample_paths": 3}
```

to the BNP request. The response then carries, from the same paths as the
price, the market as used (`market`: spot, forwards, implied yields and
rates, ATM and barrier vols per observation date, quanto drift in bp,
discount factors with and without the funding spread, the correlation
matrix), the PV of every event's coupons and redemption with the survival,
breach and loss-given-breach statistics (`decomposition`), the running
means, the zero-vol forward walk, the bond-only value and the prices with
correlation forced to 1 and to 0 (`checks`; the two limit prices are two
extra Monte Carlo runs on the same stream, so the request costs about three
times the plain one), the basket-performance and payout quantiles, a 20-bin
payout histogram and the first three paths (`distribution`), and the
milliseconds per stage (`timing`). Every quantity is defined in the doc
comments of `flatbuffers/fbs/structured_note_response.fbs` and in
`docs/http-api.md` ("Structured notes").

## Greeks

`bnp_quad_index_classic_autocall_xs2741509801_greeks.json` adds

```
"greeks": {"spot_bump": 0.01, "vol_bump": 0.01, "correlation_bump": 0.01,
           "funding_bump_bp": 1.0, "rate_bump_bp": 1.0}
```

(the defaults; `"greeks": {}` is the same request) to the BNP request, with
`monte_carlo.paths` lowered to 16 384 so that the 16 simulations fit the
JSON gateway's 10 s RPC deadline (at 65 536 paths they take about 21 s of
engine time; the gateway would return a 504). The
response then carries `greeks`: per underlying `delta` (per +1 % of spot,
central), `gamma` (per +1 %^2) and `vega` (per +1 vol point) with the
standard error of each, `correlation_sensitivity` (per +0.01 on every
off-diagonal entry) with the matrix actually used (`correlation_bumped`)
and whether it had to be repaired, `funding_dv01` and `rho` (per +1 bp),
and the bump sizes. Every bumped value is a full simulation on the same
random stream (common random numbers), so the request costs 16 runs for the
four underlyings: about 6 s through the gateway at 16 384 paths against
0.4 s for the plain request at the same path count. Definitions in
`docs/http-api.md` ("Structured notes",
"Greeks") and in the doc comments of
`flatbuffers/fbs/structured_note_response.fbs`.

## Monte Carlo settings

`monte_carlo = {paths: 65536, seed: 42, sequence: Sobol, antithetic: true,
brownian_bridge: true}` in every file (16 384 paths in the Greeks file, see
above); no `steps_per_year` because every vol
is flat and the barrier is European, so the time grid is the observation
dates only.

## How the prices are verified

`tests/contract/structured_note_parity_test.py` reprices every request file
here (the diagnostics file is the BNP request; and seven synthetic requests) with `structured_note_ql` in
`tests/contract/ql_reference.py`: an independent Python QuantLib
implementation of the market set-up, the time grid and the payoff walk
that draws from the same random sequence as the engine
(`SobolBrownianBridgeRsg`, Sobol JoeKuoD7 or Mersenne Twister, consumed
time-major, antithetic = the negated draws, pairs averaged into one
sample). On the same stream the two Monte Carlo estimates agree to the 12
decimal places the JSON gateway prints: `npv`, `standard_error`, the three
`legs`, `p_barrier_breach`, `expected_life_years`, every `p_call` /
`p_coupon` and `seasoning.memory_carried` are compared with a relative
tolerance of 1e-9 (plus 1e-11 absolute for the print rounding). With the
`diagnostics` flags on (the diagnostics file, the single-underlying file
and two synthetic requests) the reference also rebuilds the `market`,
`decomposition`, `checks` and `distribution` blocks from their definitions
in the response schema, including the correlation-one and correlation-zero
limit runs on the same stream, and every numeric field is compared the same
way (histogram counts and sample paths exactly; `timing` only for its
presence and stage names). With `greeks` on (the Greeks file at 8 192
paths, the single-underlying file with non-default bump sizes, and a
synthetic three-asset basket whose bumped correlation matrix has to be
repaired) the reference rebuilds every bumped market from the request
JSON as the engine does, forms the per-sample differences on the same
stream and is compared the same way on every Greek, its standard error,
the repaired flag and the bumped matrix. The three
files are also functional-catalog cases (`tests/functional/manifest.py`,
family "Structured Notes"). A convergence test checks that the reported
standard error scales as 1 / sqrt(paths).

## Validating the files against the schema

Inside the build image (`flatc` on PATH):

```
flatc --binary --strict-json -I flatbuffers/fbs -o /tmp \
  flatbuffers/fbs/price_structured_note_request.fbs \
  examples/data/structured_note/<file>.json
```
